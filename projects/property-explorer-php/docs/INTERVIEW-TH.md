# แนวทางอธิบายโปรเจกต์ Habitat

นี่คือเดโมที่เขียนใหม่เพื่อแสดงทักษะ ไม่ใช่ระบบของ SENA หรือผลงาน Production ย้อนหลัง โค้ดจัดทำด้วยความช่วยเหลือของ Codex ควรอ่านและลองแก้เองก่อนนำไปสัมภาษณ์

## เล่าโปรเจกต์ภายใน 1 นาที

“โปรเจกต์นี้เป็นระบบค้นหาที่อยู่อาศัยด้วย PHP/MySQL มีตัวกรองตามประเภท ทำเล และงบประมาณ พร้อมระบบหลังบ้านสำหรับเพิ่ม แก้ไข เปลี่ยนสถานะ และลบรายการ ใช้ข้อมูลสมมติทั้งหมด ส่วนที่ตั้งใจแสดงคือการออกแบบฐานข้อมูล การตรวจข้อมูลฝั่งเซิร์ฟเวอร์ การแยกสิทธิ์ผู้ดูแล และการทำหน้าเว็บให้ใช้ได้โดยไม่ต้องพึ่ง JavaScript”

## จุดที่ควรเข้าใจ

- `search_properties()` ประกอบเงื่อนไข SQL โดยใช้ placeholders; ค่า sort มาจาก allowlist เพราะชื่อคอลัมน์ bind แบบ value ไม่ได้
- `%` และ `_` ในคำค้นถูก escape เพื่อให้ค้นหาเป็นตัวอักษรจริง ไม่กลายเป็น wildcard ที่ผู้ใช้ไม่ได้ตั้งใจ
- `validate_property()` ตรวจข้อมูลฝั่ง server แม้ผู้ใช้แก้ request โดยไม่ผ่าน form
- `e()` ป้องกันข้อความจากฐานข้อมูลถูกตีความเป็น HTML ในหน้าแสดงผล
- CSRF token ตรวจคำขอที่เปลี่ยนข้อมูล แต่ไม่ใช่สิ่งทดแทน authentication
- หลัง login ต้องเปลี่ยน session ID และไม่เก็บ password แบบ plain text
- Draft ต้องถูกกรองทั้งหน้ารวมและหน้า detail ไม่ใช่แค่ซ่อนการ์ดใน UI
- Map ใช้เปอร์เซ็นต์ X/Y จึงเป็นแผนผังประกอบ ไม่ใช่พิกัด GPS

## ทดลองทำเองก่อนสัมภาษณ์

1. เพิ่มตัวกรองจำนวนห้องนอนพร้อมทดสอบกรณีไม่มีผลลัพธ์
2. เพิ่ม pagination โดยยังเก็บ filters เดิมใน URL
3. อธิบายผลของ index `(published, type, district, price)` และกรณีที่ใช้ได้ไม่เต็มประสิทธิภาพ
4. เพิ่ม integration test ตรวจว่า draft ไม่เปิดผ่าน URL โดยตรง

## สิ่งที่ควรพูดตามจริง

ใช้ AI ช่วยสร้างและปรับโค้ดได้ แต่ควรบอกว่าคุณตรวจส่วนใดและแก้อะไรด้วยตัวเอง อย่าอ้างว่ารองรับผู้ใช้จำนวนมากหรือผ่าน security audit เพราะเดโมนี้ยังไม่ได้ทดสอบด้านนั้น
